# 哔哩哔哩 iOS 登录协议（分析记录）

> 目标：`tv.danmaku.bilianime`（哔哩哔哩 iOS 9.5.0），iPhone X / iOS 16.7.15 / arm64。
> 手段：IOSDecryptHub 进程内 hook（`query_events` / `get_event`）+ 运行时 SNI 抓取 + 脱壳 IPA 离线分析。
> 本文只记录协议结构，不含任何真实密钥、设备标识或账号数据。

## 1. 结论摘要

| 项目 | 内容 | 证据等级 |
|---|---|---|
| 登录主机 | `passport.bilibili.com` | **实测**（点「登录」瞬间捕获 ClientHello SNI + DNS 解析） |
| 登录路径 | `/x/passport-login/oauth2/login` | 二进制字符串表（与 `device_meta` 同表；静态未见直接引用，运行时索引/拼接） |
| 传输方式 | appkey 方案（query string 签名） | 由签名入参结构实测得出 |
| 密码 | `base64(RSA-PKCS1v1.5(salt8 + plainPassword))` | **逐字节复核** |
| 请求密钥 | `base64(RSA-PKCS1v1.5(salt8 + aesKey16))` → `dt` 参数 | **逐字节复核** |
| 设备指纹 | `hex(AES-128-CBC-PKCS7(key=iv=aesKey, deviceJSON))` → `device_meta` | **逐字节复核** |
| 签名 | `MD5(待签名 query string)` → `sign` | **逐字节复核** |

## 2. 实测链路（一次点「登录」的完整顺序）

同一线程内按下述顺序执行（seq 为 IOSDecryptHub 事件号）：

1. `RSA-PKCS1v1.5` 加密 `salt(8B, hex) + 明文密码` → 128B → base64 → `password`
2. `AES-128-CBC-PKCS7`（key = iv = 随机 16 字符 ASCII）加密 48 字段设备指纹 JSON → hex → `device_meta`
3. `RSA-PKCS1v1.5` 加密 `salt + aesKey` → 128B → base64 → `dt`
4. `MD5(整条待签名 query string)` → 32 hex → `sign`

复核方式（对同一事件做字节级等式）：

```
base64(hex→bytes(rsa_event.output))      == query["password"]
base64(hex→bytes(rsa_key_event.output))  == query["dt"]
hex(aes_event.output)                    == query["device_meta"]
md5(待签名串)                             == query["sign"]
```

四项当时全部为 True（脚本见本轮会话记录）。

## 3. 待签名串（参数表）

`actionKey=appkey` 方案，参数按序拼接后取 MD5：

| 参数 | 说明 |
|---|---|
| `actionKey=appkey` | 固定 |
| `appkey` | 16 位十六进制，版本相关常量 |
| `bili_local_id` / `local_id` / `buvid` / `device_id` | 设备标识（服务器/本地生成） |
| `build` / `channel` / `mobi_app` / `platform` / `device` / `spm_id` | 客户端元信息 |
| `device_name` / `device_platform` / `device_tourist_id` | 机型与游客 ID |
| `device_meta` | AES 加密后的设备指纹（48 字段：idfa/idfv/屏幕/内存/磁盘/root 标志/生物识别/电池等） |
| `dt` | RSA 包裹的本次 AES 密钥 |
| `password` | RSA 包裹的密码 |
| `login_session_id` / `ts` / `statistics` / `disable_rcmd` | 会话、时间戳、统计 |
| `username` | 账号 + 32 位十六进制常量后缀（该后缀在二进制中为固定字符串，非账号派生） |

> 说明：字符串在进入 MD5 前**已完成 percent 编码**（`@`→`%40`、`/`→`%2F`、`=`→`%3D`），签名覆盖的是编码后的形式。

## 4. 为什么最初抓不到 HTTP 报文

- 该请求走 App 自研网络栈：**裸 BSD socket + 自带 TLS**，不经过 `NSURLSession` / `NSURLConnection`，也不调用 OpenSSL 的 `SSL_write`。
- 现有 hook 覆盖（NSURLSession / SSL_write / nw_connection_send）对它全部失效；只有 `connect` / `getaddrinfo` 能看到。
- **已补齐**：新增 `getaddrinfo`(DNS) / `connect`(SOCKET) / `send` 解析 ClientHello SNI(TLS) / Apple SecureTransport `SSLWrite/Read` / `nw_connection_send` 覆盖后，点登录即可看到
  `TLS fd=… passport.bilibili.com` + `DNS passport.bilibili.com rc=0`。

## 5. 风控侧观察

- 每 60 秒一次心跳：`sysctl(调试状态探测)` → `uname` → `AES-256-CBC` → `POST https://api.bilibili.com/x/internal/gaia-gateway/ExBadBasket`（1KiB 密文）。
- 该心跳与登录请求走不同网络层，抓取正常。

## 6. 尚未闭合

- HTTP 方法/头字段的**直接观测**（需要在其自研栈的发送边界挂钩，或在业务层 hook 构造请求的对象）。
- `username` 32 位后缀的语义（已知为二进制内固定常量，非账号派生）。

### 6.1 已排除的取证路径（避免重复劳动）

| 尝试 | 结果 |
|---|---|
| 字符串交叉引用（自研离线工具，支持裸指针 / chained fixups / 4 字节相对指针 / 区间扫描） | `x/passport-login/oauth2/login` **无直接引用**；同簇其它字符串（如 `BFCMultiTheme` 相关）都有 `ADRP+ADD` 引用 → 该路径是运行时拼装/索引，静态引用天然不存在 |
| App 自身网络日志库（`Documents/BLog/*.blog`、`Library/Application Support/neuron/kmp_neuron.db` + WAL，经 SSH 全量拉取） | 无 `passport` 明文记录（日志为二进制/加密形态） |
| 导入表探针（`SSL_write` / `nw_connection_send` 等） | 登录流量不经过这些可 hook 的 API（自研栈 + 裸 socket + 自带 TLS） |
| 运行时可观测的部分 | **host 已实测**（登录瞬间 `TLS fd=… passport.bilibili.com` + DNS 解析），参数与四段加密全部实测并逐字节复核 |

因此该请求的 HTTP 方法/头字段与 CM 的 RSA 明文属于**同一类边界**：明文只存在于 App 自带的静态 TLS/HTTP 栈内部，GOT 级 hook 不可达，inline hook 与项目铁律冲突。

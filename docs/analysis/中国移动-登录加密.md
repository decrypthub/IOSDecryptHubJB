# 中国移动 iOS 登录加密（分析记录）

> 目标：`cn.10086.app`（中国移动 iOS 12.5.2），iPhone X / iOS 16.7.15 / arm64。
> 手段：IOSDecryptHub 进程内 hook + 设备端接口码表（`BousCode.json`）+ 未加密框架离线分析（`CMApiManager.framework`）。
> 本文不含真实密钥、手机号、设备标识或令牌；涉密常量只给前缀。

## 1. 登录方式

登录页提供「手机号 + 短信验证码」与「人脸识别登录」。本文覆盖短信验证码登录链路的**请求构造与加密**（未点「获取验证码」，避免向任何真实号码发短信：直接填占位号码 + 假验证码提交，只看加密构造）。

## 3. 手机号加密（两级）

1. `AES-128-ECB-PKCS7`，key = 固定 16 字符 ASCII（二进制常量，前缀 `9e5702…`），输入 11 位手机号 → 16 字节。
2. `reqBody.cellNum` = 128 字节密文（RSA-1024 量级），**未命中任何已 hook 的 RSA API**：
   - `SecKeyCreateEncryptedData`（新版 Security）无事件
   - `SecKeyEncrypt`（旧版 Security）探针 0 命中
   - 主二进制也没有 OpenSSL `EVP_*` / `RSA_*` 导入
   → 判定为 App 内**自研/静态链接**的 RSA 实现，属于 IDH 的已知盲区（无法用 GOT 级 hook 覆盖，inline hook 与项目铁律冲突）。

## 4. 旁路：埋点与风控

- 极光埋点：`POST https://jiguang.coc.10086.cn/v3/projects/<id>/collect`，带 `X-Crypt-Codec: 1`、`X-Compress-Codec: 3`。
- 登录被拒时服务端返回 `【310000】当前网络异常` —— 属于服务端风控判定（假号码/假验证码 + 环境风险都可能触发）。

## 7. cellNum 取证结论（受控实验 + 公钥验证）

对 128 字节的 `reqBody.cellNum` 做了以下判定实验：

| 假设 | 判据 | 结果 |
|---|---|---|
| 含随机性 | 同手机号/同假验证码两次请求，其它字段全同、`cellNum` 完全不同 | ✅ 随机化 |
| SM2（C1‖C3‖C2） | 前 64/65 字节按 SM2 曲线方程验点 | ❌ 不是曲线点 |
| AES-CBC/ECB（用请求链路里已知的两把密钥 × 4 种 IV） | PKCS7 填充合法性 | ❌ 无合法填充 |
| 裸 RSA（教科书式） | 用**二进制里抠出的两个 1024 位公钥**分别对候选明文做 `m^e mod n` 比对 | ❌ 不匹配 |
| **RSA-1024 + 随机填充（PKCS#1 v1.5 / OAEP）** | 128 字节 = 1024 位块长；两次密文不同；裸 RSA 已排除 | ✅ 与全部观测一致 |

公钥来源：`ChinaMobile` 主二进制内嵌两条 1024 位 RSA 公钥（base64 SPKI，均以 `MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQKBgQ…` 开头），已导出并解析确认位数与指数 `e=65537`。

补充：该 RSA 实现**不在任何镜像的导入表**里（`RSA_public_encrypt` / `EVP_PKEY_encrypt` / `SecKeyEncrypt` 等探针全部返回「未在导入表」或 0 命中），属静态链接，GOT 级 hook 无法覆盖；项目铁律又禁止 inline hook，因此**明文只能在调用层取证**——当前最强证据是：同一次登录里 `AES-128-ECB(手机号)` 的 16 字节输出在请求其它字段中均未出现，指向 `cellNum = RSA_padded(AES_ECB(phone))`（待运行时证实）。

### 7.1 明文取证的最终边界（已穷尽 GOT 级手段）

为拿到 RSA 的明文输入，逐类试过并全部 **0 命中**：

| 探针 | 结果 |
|---|---|
| `hook_method(describe_args:true)` × 8 个运行时加密入口：`HPRSAEncryptor.encryptData:publicKey:`、`NewsPushRSA.encryptData:publicKey:`、`SecurityCipher.encryptBinary:key:`、`HPEncryptorManager.encryptBody:`、`CMCCRequestLogManager.encryptString:withKeyType:`、`GNTaskExecutor.encryptSensitiveData:`、`ZJCLifeService.encryptParam:`、`BCEAes.aes128_encryptData:withKey:` | 全部 0 命中（这条链路不经过任何 ObjC 加密封装） |
| `hook_import` × 4 个 RSA 符号（`RSA_public_encrypt` / `EVP_PKEY_encrypt` / `SecKeyEncrypt` / `CCRSACrypt`） | 全部「不在导入表」 |
| `hook_import` × 2 个随机数 API（`CCRandomGenerateBytes` / `SecRandomCopyBytes`，用于捕获 PKCS1 填充缓冲） | 能绑上但 0 命中（实现自带 RNG） |
| 内嵌私钥搜索（PEM 私钥头 / ≥800 字符 base64 块） | 无（只有一个 X.509 证书） |

结论：该 RSA 是**完全自包含的静态实现**（自带大数运算 + RNG），在不使用 inline hook 的前提下其明文不可观测。已用「同批次其它字段全部排除 + AES-ECB(手机号) 输出无处可去」把明文收敛到唯一合理候选 `AES_ECB(phone)`。

### 7.2 与风控的交互（实测）

- 同一号码连续失败后，服务端/客户端会直接返回 `【310000】当前网络异常`，且**不产生任何加密调用**（请求在本地就被拦）；
- 换一个未用过的号码后，完整链路立刻恢复，服务端返回的是业务错误（`验证码无效，请使用本机获取验证码`）。
- 该 App 内置 Bangcle everisk 反检测（Frida/TrollStore/代理/root/swizzle/inline-hook/fishhook 检测），其检测路径清单已并入 IDH 默认隐藏清单。

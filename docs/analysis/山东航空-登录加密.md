# 山东航空 iOS 账号密码登录加密（分析记录）

> 目标：`cn.com.shandongair.m`（山东航空 iOS 5.3.1，build 11680）。
> 环境：iPhone 11（`iPhone12,1`）/ iOS 16.2 / roothide，arm64e，IOSDecryptHub 1.27.3。
> 手段：进程内 `hook_import` + 1.27.3 新增的 `capture_memory` 参数内存快照 + 事件里的 HTTP 明文。
> 本文不含真实手机号、口令、设备标识或令牌；示例值一律用占位符。

## 1. 登录方式与触发

登录页提供「验证码登录」与「账号密码登录」。本文覆盖账号密码链路：

1. 输入占位手机号与假口令；
2. 首次点「登录」弹出隐私协议，点「同意并登录」；
3. 抓包时 App 返回「账号或密码错误」，说明登录请求已完整构造并发出（假凭据不会触发真实登录）。

## 3. 请求体加密

```
body = {"param": Base64( AES-128-ECB-PKCS7( JSON ) )}
```

- **算法：AES-128-ECB，PKCS#7 填充，无 IV。**
- key：**App 二进制内硬编码的 16 字节 ASCII 常量**（在 `__TEXT,__const`，本次 dump 的 RVA `0x1025f1de0`）。
  运行时由 CryptoSwift 读入并 `mlock` 锁定；同一进程内 3 次登录（间隔 76 分钟）抓到的 key 完全相同，
  且该 16 字节字符串在 App 二进制里只出现一次，排除了“每次请求随机生成”。
- 密文长度 432 字节（明文 430 字节 + 2 字节 PKCS#7 填充），Base64 后放进 `param`。

✅ **实际解密验证**：用 `capture_memory` 在 `mlock` 命中瞬间抓到的 16 字节 key 解 `param` → 得到完整业务 JSON；
本地再 `AES-128-ECB-PKCS7` 回加密，Base64 结果与事件里的 `param` **逐字节一致**（round-trip match），确认算法与 key 均无歧义。

重复性证据（同一 App 进程 PID 15340，三次登录）：

| 时间 | 登录 HTTP seq | mlock seq | 抓到的 key |
|---|---|---|---|
| 18:54:24 | 7477 | 7476 | 16 字节常量 K |
| 20:10:46 | 38812 | 38811 | K（相同） |
| 20:10:46 | 38827 | 38826 | K（相同） |

三次的 `sessionId` / `deviceKey` / `timeStamp` 都不同，key 不变 → key 不是请求级随机，而是 App 内常量
（常量在二进制中，预计同版本设备一致；跨设备未验证）。

## 4. 为什么 1.27.2 之前抓不到 key

| 阶段 | 现象 | 原因 |
|---|---|---|
| 只装 `hook_import(mlock)` | 能命中一次：`x0=key指针, x1=16`，但事后用 `read_memory` 回读只剩零/已复用内容 | 旧版 hook 只保存寄存器快照，不保存指针指向的内存；CryptoSwift 在加密开始后很短时间就释放/复用该缓冲区 |
| 1.27.3 `capture_memory` | `hook_import(mlock, capture_memory={ptr_arg:0, len_arg:1, max_bytes:4096})` 命中瞬间拷贝 16 字节到事件 `input` | 拷贝发生在 thunk handler 内、原函数尚未返回，缓冲区内容仍有效 |

补充证据：key 常量本身就在 dump 出来的二进制里（`__TEXT,__const`，该 16 字节字符串全文件只出现一次）。
即使没有动态捕获，**dump + 字符串检索**也能找到这个候选常量；`capture_memory` 的价值是证明“这个常量就是 AES key”，
并覆盖那些 key 不落在二进制、只在运行时存在的 App。
`find_string_refs` 对该常量返回 0 条直接引用 —— 它位于一张混合了混淆字节的字符串常量表里，代码很可能按表基址 + 偏移访问，
不是标准 `ADRP+ADD` 引用；这不影响密钥结论（解密 + 回加密已闭环）。

静态链路印证：`mlock` 的返回地址落在 CryptoSwift AES 初始化代码（静态地址 `0x10109c228` 附近，wrapper `0x10109c15c` / core init `0x10109c1c0`）。
CryptoSwift 是**静态链接**，不走 CommonCrypto / Security / ObjC 加密封装，因此普通 crypto hook 全部无事件，只能从 `mlock` 这类标准库导入符号切入。

## 5. 这次用到的通用能力

```json
{
  "name": "hook_import",
  "arguments": {
    "symbol": "mlock",
    "label": "cryptoswift-key-buffer",
    "capture_memory": { "ptr_arg": 0, "len_arg": 1, "max_bytes": 4096 }
  }
}
```

- `ptr_arg` / `len_arg` 是 x 寄存器索引，不包含任何 App 特判；任何「指针 + 长度」型 C API（`mlock`、`read`、`send`、`CC_*` 等）都能用同一套配置抓内存。
- 捕获结果写入事件的 `input`，`get_event` 直接返回 `inputHex` / `inputUtf8` / `inputDump`。
- 仍只改 GOT/IMP 指针，不引入 inline hook、trampoline 或可执行内存，符合免越狱架构铁律。

## 6. 复现步骤

1. 设备安装 1.27.3+，冷启动山东航空；
2. MCP 安装 `mlock` hook（配置见上）；
3. 进入「账号密码登录」，填占位手机号 + 假口令，点「登录」→「同意并登录」；
4. `query_events(category:"other", keyword:"mlock")` 取事件 seq，`get_event` 读 `inputHex`（16 字节 key）；
5. `query_events(category:"net", keyword:"login4UserNamePassword")` 取 `param`；
6. 用 key 做 `AES-128-ECB-PKCS7` 解密 `Base64(param)` 得到业务 JSON。
